# Objective
Add a policy-laundering failure mode and provenance-retention benchmark so OpenClaw-Govern evaluates sanitized-intermediate bypasses as a composition problem, not just a prompt-injection variant.

# Background
- The queue item selected for this run is the policy-laundering / prompt-injection-derived failure mode with provenance-retention scoring.
- `docs/evaluation-plan.md` already sketches S10 as a sanitized-summary laundering case, but the repo still treats it as a proposed extension rather than a fully scored benchmark row.
- `paper/07_evaluation.md` and `results/EVALUATION_SUMMARY.md` currently keep the laundering case outside the reported counts, so the next increment should make the benchmark/export path and the prose agree on what is actually measured.
- The novelty claim should stay centered on composition: ordered runtime modules, deterministic arbitration, authorization propagation, async controls, and unified traces across heterogeneous controls.
- The laundering case is useful because it stresses the interface between delegation, sanitization, and evidence retention: a child agent can transform unsafe intent into a benign-looking summary unless provenance survives the adapter boundary.
- AgentArmor is the clearest precedent for reconstructing runtime traces into analyzable graph structure.
- AuthGraph is the strongest provenance/authorization comparison because it aligns execution provenance against authorization expectations at parameter-source granularity.
- VIGIL gives a verify-before-commit precedent for tool-stream injection and delayed commitment under untrusted intermediate output.
- Trace-based assurance work reinforces the need for replayable traces, step-local contracts, and explicit governance evidence rather than output-only checks.

# Proposed change
Concrete file-level increment for the builder:

1. `docs/evaluation-plan.md`
   - Promote the laundering case from “proposed extension” wording to a scored benchmark scenario.
   - Keep the scenario description centered on a sanitized summary that hides an unsafe original request.

   - State that the adapter/summarizer must remain visible so lineage loss is auditable.

2. `experiments/composition_benchmark.py` and `experiments/composition_benchmark_real_adapters.py`

   - Preserve the original request in trace metadata even when the intermediate text is sanitized.
   - Keep the benchmark deterministic so the builder can regenerate a stable CSV.

3. `results/generate_plots.py`, `results/composition_benchmark.csv`, `results/composition_benchmark_real_adapters.csv`, and `results/EVALUATION_SUMMARY.md`
   - Surface `provenance_retained` in the summary/export path.
   - Regenerate any affected counts together so the paper, CSV, and summary do not diverge.
   - If the new scenario changes totals, update the reported benchmark count everywhere in the same increment.

4. `paper/07_evaluation.md` and `paper/08_related_work.md`
   - Add one short sentence explaining that the laundering case is scored separately on provenance retention, not only verdict correctness.
   - Keep the related-work framing explicit that AgentArmor/AuthGraph/VIGIL/trace-based assurance motivate the evidence model, while OpenClaw-Govern contributes the composition layer.
