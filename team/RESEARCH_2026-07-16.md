# Objective
Tighten the policy-laundering / provenance-retention increment so the benchmark and related-work sections make the laundering boundary testable without recentering the paper on prompt-injection defense.

# Background
- The queue already tracks a policy-laundering scenario where unsafe intent is rewritten into a benign-looking summary before downstream execution.
- `docs/evaluation-plan.md` already defines S10 and says the original intent must remain recoverable across the adapter / summary boundary.
- `paper/07_evaluation.md` and `docs/related-work.md` already mention `provenance_retention`, but the manuscript needs one more pass so the metric is tied to the composition story rather than treated as a standalone anti-injection claim.
- The current blocker in `team/STATE.md` is a latency-table drift in `paper/07_evaluation.md`; this increment should avoid touching the published overhead numbers unless the CSV/summary is deliberately regenerated.
- AgentArmor is the clearest precedent for reconstructing agent runtime traces as analyzable graph programs.
- AuthGraph is the closest provenance/authorization split because it compares injected execution provenance against a clean authorization baseline at parameter-source granularity.
- VIGIL provides a complementary tool-stream-injection precedent for verify-before-commit under dynamic dependencies.
- A trace-based assurance framework gives the strongest runtime-governance framing for contracts, replay, and governance metrics over message-action traces.
- OpenClaw-Govern’s novelty should remain centered on the composition layer: ordered runtime modules, deterministic arbitration, and unified traces across heterogeneous controls.
