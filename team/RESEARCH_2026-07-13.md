# Objective
Add a policy-laundering / prompt-injection-derived composition failure mode so the paper explicitly covers cases where unsafe intent is transformed through summaries or adapters and must be caught by provenance-preserving governance.

# Background
- The current motivation section defines eight composition failure modes, but it does not yet name a case where unsafe intent survives by being re-expressed through an apparently benign intermediate representation.
- `docs/publication-gap-analysis.md` already flags policy laundering as an open problem; that gap is not yet reflected as a named scenario in the paper or evaluation plan.
- Prompt-injection literature shows that untrusted inputs can hijack agent behavior, and that existing defenses often fail to generalize when context-dependent reasoning is required.
- `AgentArmor` is a strong precedent for treating agent runtime traces as structured programs with analyzable provenance, which is exactly the kind of machinery needed to detect laundering through adapters or summaries.
- The trace-based assurance framework likewise treats executions as message-action traces with contracts, local violation localization, and deterministic replay, making trace provenance central rather than optional.
- This increment should keep the core novelty centered on composition: ordered runtime modules, provenance-preserving traces, and deterministic arbitration across heterogeneous controls.
- The benchmark value is not merely that the system blocks unsafe text; it is that it preserves enough lineage to show that a sanitized intermediate did not erase the original unsafe intent.

# Proposed change
Update the paper/docs surface as follows:

1. `paper/02_motivation.md`
   - Add a ninth failure mode under §2.4, tentatively named `policy_laundering`.
   - Use a concrete example where a child agent sanitizes an unsafe request into a benign-looking summary before passing it to a downstream executor.
   - State the root cause as provenance loss across adapters / summaries, which allows output-only checks to miss the original unsafe intent.

2. `docs/evaluation-plan.md`
   - Add a matching benchmark scenario with a deterministic expected verdict of `DENY`.
   - Require the trace to preserve the original intent provenance, not just the sanitized intermediate text.

3. `paper/07_evaluation.md`
   - If the benchmark is extended, update the scenario list, table counts, and prose so the new scenario is described consistently with the motivation section.
   - Make the trace-completeness discussion explicitly mention provenance through the sanitizing adapter.

4. `paper/08_related_work.md` and `docs/related-work.md`
   - Add a short positioning note that prompt-injection / trace-analysis work motivates provenance-preserving governance, but the novelty remains the composition layer that orders, arbitrates, and traces heterogeneous runtime modules.

# Acceptance criteria for builder
1. `paper/02_motivation.md` contains a new named failure mode that concretely describes unsafe intent being laundered through a sanitized intermediate representation.
2. `docs/evaluation-plan.md` contains a matching scenario with an unambiguous expected verdict and a trace requirement that preserves original provenance.
3. `paper/07_evaluation.md` is either updated to include the new scenario or explicitly left unchanged with a note explaining that the benchmark extension is pending; no silent drift in counts or labels.
4. `paper/08_related_work.md` and `docs/related-work.md` frame prompt-injection and trace-analysis papers as precedent for provenance-preserving governance, not as the novelty claim itself.
5. The new scenario’s terminology matches across motivation, evaluation plan, and related-work notes.
