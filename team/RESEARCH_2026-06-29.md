# OpenClaw Research Increment — 2026-06-29

## Objective
Add a benchmark scenario that tests unified trace completeness under mixed governance conflicts and delegation chains, not just final verdict selection.

## Background
OpenClaw-Govern already positions itself as a composition layer for SARC-style constraints, authorization propagation, async controls, ROMA-style delegation, and unified traces.
The current deterministic composition benchmark in `experiments/composition_benchmark.py` covers 8 scenarios, but the paper’s evaluation still emphasizes verdict accuracy more than trace reconstruction.
`docs/evaluation-plan.md` already lists an `audit reconstruction` scenario, which suggests the benchmark surface is expected to include trace-completeness testing.
The related-work matrix distinguishes OPA decision logs and OpenTelemetry-style traceability from OpenClaw’s runtime governance composition, but the paper does not yet turn that distinction into a dedicated scenario.
ROMA is useful here because its recursive hierarchy gives a natural delegation-chain backbone for trace references, but ROMA alone does not define cross-module governance arbitration.
XACML combining algorithms provide a precedent for deterministic decision arbitration, yet they do not cover trace completeness across heterogeneous modules.
A trace-focused benchmark would make the paper’s unified-trace claim concrete and measurable, rather than implicit.

## Proposed change
Add a ninth scenario to the composition benchmark, centered on unified trace reconstruction.

File-level changes for builder:
- `experiments/composition_benchmark.py`
  - add a `trace_reconstruction` or `audit_reconstruction` task with a concrete expected final verdict
  - emit trace-completeness metadata in the row/CSV export so the scenario can be scored on evidence presence, not only verdict accuracy
- `experiments/composition_benchmark_real_adapters.py`
  - mirror the same scenario with real adapters and ensure trace fields survive short-circuit / conflict resolution
- `paper/07_evaluation.md`
  - replace the current 8-scenario framing with 9 scenarios, or add a dedicated paragraph/table row for trace reconstruction
  - report trace completeness as a first-class metric alongside accuracy and latency
- `docs/evaluation-plan.md`
  - add a new scenario entry for trace reconstruction / audit reconstruction to keep the plan aligned with the benchmark harness
- `paper/06_trace_tree.md` or `paper/05_ordering_semantics.md`
  - clarify that short-circuited modules must still leave explicit skipped/blocked trace markers

Suggested scenario shape:
- an action with a delegation chain plus overlapping governance concerns (e.g. delegated write attempt + semantic risk + async correlation)
- expected final verdict: `DENY`
- expected trace property: all intervening modules are either represented in the trace or explicitly marked as skipped, enabling post-hoc reconstruction
