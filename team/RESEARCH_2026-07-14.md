# Objective
Add a provenance-retention / trace-completeness metric to the policy-laundering benchmark so sanitized intermediates are scored explicitly, not just described in prose.

# Background
- The current queue item already names the policy-laundering / prompt-injection-derived failure mode, and `docs/evaluation-plan.md` already contains S10 with the right expected verdict (`DENY`).
- The paper and evaluation prose now mention that a sanitized summary or adapter must not erase the original unsafe intent, but the benchmark/export layer still lacks a dedicated score for provenance retention.
- The latest reviewer blocker is about the benchmark snapshot and summary artifacts drifting out of sync; adding an explicit retention metric makes the laundering case auditable in the same export path rather than only in prose.
- Prompt-injection work is relevant here because the attack surface is not just a bad final string; it is the loss of original intent across a context-changing boundary.
- AgentArmor is the closest precedent for treating runtime traces as analyzable programs, especially when provenance must survive trace reconstruction.
- The trace-based assurance framework is also directly relevant because it turns executions into message-action traces with contracts, replay, and governance metrics that can surface where provenance was lost.
- OpenClaw-Govern’s novelty remains the composition layer: ordered runtime modules, deterministic arbitration, and unified traces across heterogeneous controls.

# Proposed change
Concrete file-level increment for the builder:

1. `docs/evaluation-plan.md`
   - Keep S10 as the policy-laundering scenario.
   - Add an explicit metric for `provenance_retention` (or equivalent wording) that checks whether the original unsafe request remains recoverable through the adapter / summary boundary.
   - State that the expected trace must preserve the laundering chain, not only the final DENY verdict.

2. `paper/07_evaluation.md`
   - Add one sentence clarifying that the reported 10-scenario counts stay unchanged until the benchmark harness is extended.
   - Add a short metric note so the laundering scenario is evaluated on both verdict correctness and provenance retention.

3. `results/generate_plots.py` and the associated summary export path
   - Emit a trace-retention / provenance-retention field in the generated summary so the laundering scenario can be compared across runs.
   - Preserve the current benchmark counts and latency table, but surface lineage-loss separately instead of hiding it inside prose.

4. `docs/related-work.md` and `paper/08_related_work.md`
   - Keep the current AgentArmor / trace-based assurance framing, but tie it explicitly to the new metric so the provenance-preserving claim is backed by the evaluation surface.
